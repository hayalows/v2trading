# V2 Trading UI/UX Audit — 2026-08-18

Baseline: production app-v3 before this audit pass.

## Standards used
- Apple HIG: visual hierarchy, alignment, progressive disclosure, adaptability, typography, accessibility.
- Android/Material guidance: 3–5 primary destinations, adaptive navigation, containment, alignment, reduced action density, responsive/adaptive layouts.

## Key findings
1. Home is generally strong after the recent compact-account pass, but secondary account metrics still compete slightly with instrument state on narrow devices.
2. Trades combines two distinct user jobs in one long page: monitoring the current setup and reviewing historical trades. This creates unnecessary vertical travel and weakens focus.
3. Trade history progressive loading is correct, but the user still has to scroll past live instrument progress to reach history every time.
4. Research uses horizontal swipe cards. This reduces vertical length but weakens discoverability and creates a hidden-content problem; a disclosure list is clearer for evidence/research content.
5. System presents all diagnostics with similar emphasis. Core operational health should be visible first; deeper diagnostics should be disclosed on demand.
6. Intermediate/tablet layouts are under-specified. Current design jumps mostly from phone to desktop rail at 900px.
7. No prefers-reduced-motion treatment exists.
8. Some very small metadata remains in the base stylesheet; later overrides fix many instances, but the system is harder to maintain because the same selectors are repeatedly overridden.
9. Chart mobile focus is good, but it can be further simplified by using a single segmented pair control and keeping the chart as the dominant viewport element.
10. The five primary destinations are appropriate for bottom navigation on compact screens and rail navigation on desktop; retain this structure.

## Changes approved for this pass
- Add Trades sub-navigation: Live / History. Keep live setup monitoring and historical journal separate without adding a new top-level destination.
- Keep history filters and progressive loading inside History only.
- Replace Research mobile carousel with compact disclosure rows.
- Split System into Core health + Advanced diagnostics disclosure while preserving all diagnostic data.
- Add prefers-reduced-motion handling and smoother focus/scroll behavior fallbacks.
- Improve intermediate-width layout and constrain reading widths where appropriate.
- Keep current local SVG icons, system-font stack, bottom navigation, lazy TradingView, lazy Research fetch, recovery fallback, and all trading/Discord/backend logic unchanged.

## Non-goals
- No strategy, risk, trade detection, portfolio, scheduler, Discord or Supabase behavior changes.
- No new external UI/runtime dependency.
- No icon font or remote font dependency.
